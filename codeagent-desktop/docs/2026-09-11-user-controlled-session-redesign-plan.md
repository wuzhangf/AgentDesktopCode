# CodeAgent Desktop：用户主导会话与紧凑桌面工作台优化方案

日期：2026-09-11。状态：待实施；本文不表示桌面端已完成改造。

实施入口为 `apps/codeagent-desktop`，技术栈为 Electron + React + TypeScript。本文根据用户逐项确认的产品决定和当前桌面源码编写，交给后续 AI IDE 连续实施。参考 [Web 会话重设计](2026-09-11-user-controlled-session-redesign-plan.md)，共享产品语义与服务协议，不复制 Vue 组件。当前工作树已有 Web、Service、合同和文档修改，实施前必须检查并保留这些修改，不重置工作树、不重复执行历史清理。

## 1. 目标、范围与优先级

用户掌握工作区归属、会话合同、完全访问和停止操作；模型根据用户命令选择目录、规划、调用工具和启动 subagent。取消强制理解、计划、审批计划、自主等级和应用默认轮次等打断会话的流程。真实权限不足、操作系统拒绝、供应商错误需要准确反馈。

本期完成桌面真实入口布局、会话新建与移动、合同编辑、完全访问、下一轮生效、工作状态浮动面板、工具权限和 subagent 的端到端接入。工作区改名、删除、默认目录管理等可后续实施。未来统一执行黑名单仅预留协议位置，不在本期借此保留旧审批链。

本文优先于旧桌面 UI 方案中冲突的命令面板、模式选择器、固定阶段和审批设计。源码已有实现只是核查起点，不能凭类型存在或 Web 测试通过认定桌面完成。无冲突的秘密保护、IPC 来源校验、离线资源、事件去重、分页及故障如实展示继续保留。

## 3. 最终布局

最新布局决定：**左上角保留 Logo，固定两列，无菜单栏，其余功能使用左右分组的浮动面板：左侧合同和配置，右侧 Git 和状态。** 本节替代此前合同和状态常驻占据左列空间的布局，执行权限等产品语义不变。

```text
┌ Logo ──────────────┬ 会话标题 ─────────────────────── [—][□][×] ┐
│ 工作区 / 会话       │ 消息正文直接开始                           │
│ 工作区 A [+]        │                                            │
│   会话 1 / 会话 2   │                                            │
│ 无工作区会话        │                                            │
│ [新建会话]          │                                            │
│ ┌ 左侧浮动面板 ────────┐          ┌ 右侧浮动面板 ─────────────┐ │
│ │ 合同 / 配置          │          │ Git / 状态                │ │
│ │ 目录、权限、设置     │          │ diff、分支、活动、子任务   │ │
│ └──────────────────────┘          └───────────────────────────┘ │
│ [编辑合同] [配置]   │                           [Git] [状态]    │
│                    │ 输入框 + 紧凑选项 + 发送/停止              │
└────────────────────┴────────────────────────────────────────────┘
```

图中左右面板是覆盖层，可按需打开；底层始终只有导航、对话两列，不形成四列布局。

### 3.1 Logo、单行标题与无菜单栏

- 左上角保留现有 Logo，与右列会话标题处于同一行，不增加独立品牌工具栏或第三列图标栏。空会话标题显示“新会话”。
- 会话标题与窗口标题栏合并，建议高度 32–36 CSS px；最右侧仅最小化、最大化/还原、关闭三个按钮。
- 不显示应用菜单栏；Electron 主进程移除当前应用菜单，不能只靠 CSS 隐藏，也不能通过 Alt 再展开旧菜单栏。保留必要的编辑和窗口快捷键，通过明确的快捷键处理实现。
- 删除标题栏工作区名称/选择、命令面板、会话搜索、服务徽标和设置按钮；左侧重复搜索框也移除。合同和配置入口位于左侧，Git 和状态入口位于右侧，不形成横向菜单栏，也不放入窗口控制区。
- 删除第二层 `session-header` 容器或将标题并入唯一顶栏；删除 `CONVERSATION · 已加载 N 条消息` 整行、分隔线、留白和附属菜单。
- 顶栏剩余空白可拖动，Logo 和按钮的交互区不可拖动；双击拖动区切换最大化。最大化/还原图标随主进程真实状态变化。
- Windows 使用单一自定义标题栏方案，例如 `frame: false` 配合已有窗口安全配置；不得同时留下系统标题栏和自绘顶栏。验证缩放、恢复、关闭和高 DPI。
- 窗口控制由窄 IPC 接口处理固定动作枚举，主进程校验发送窗口并操纵对应窗口；Renderer 不使用 `window.close()` 模拟桌面控制。订阅在卸载时解除。

### 3.2 两列与浮动面板

- 固定布局只有左侧导航和右侧对话两列。左列建议宽 260–320 px，可调宽；工作区/会话列表独立滚动，底部功能入口固定可见。
- 左侧“编辑合同”“配置”和右侧“Git”“状态”入口一眼可见，不藏进 Logo、盾牌或更多菜单。点击打开浮动面板，不能展开成常驻第三列，也不能推挤正文或占据对话顶部高度。
- 浮动面板按职责固定分组：左侧合同和配置，含目录、权限、归属移动、模型与应用设置；右侧 Git 和状态，含变更、分支、worktree、执行活动、subagent、终端和证据。删除独立 Plan 产品入口；用户要求的计划作为普通消息输出。
- 浮动面板覆盖在现有两列之上，提供清晰标题、关闭按钮与内部滚动；左组从左侧打开，右组从右侧打开，左右可同时显示，各组内部一次显示一个面板，组内切换保留未保存合同草稿。面板可调整大小，保持所属侧锚定，不自动停靠成固定列；窗口缩小时限制面板尺寸并使用内部滚动，保证关闭按钮可达。
- 普通面板不使用阻塞整窗的遮罩，用户仍可阅读和输入；Escape 关闭当前获得焦点的面板，关闭后焦点回入口。必要的删除确认或文件选择对话框按其原有职责工作。
- 合同浮动面板提供保存/取消、目录选择/修改/勾选、写开关、归属移动和完全访问；展示基础模式、目录数量、当前轮设置及“已保存，下一轮生效”。关闭面板不能隐式保存或丢弃草稿。
- 工作状态浮动面板实时展示净增删、文件数、分支、worktree、当前动作、累计活动和 subagent。关闭仅隐藏展示，不停止后台执行或清空统计；再次打开读取最新快照。右侧状态入口可附紧凑活动计数，不另建常驻状态区域。
- 新建页沿用同一两列结构，通过浮动合同面板设置，命令输入在右列，取消旧模式卡片及强制 Spec 模板。

### 3.3 中间对话

单行标题下直接进入消息；底部仅输入和紧凑必要控件。取消 composer 上方自动批准调度、倒计时、权限模式选择、自主程度、固定验证阶段等常驻区域。模型/推理/上下文配置合并为紧凑行或按需弹层，附件不产生空占位区域。保留历史分页、虚拟滚动、用户阅读位置；正在阅读旧消息时不强行滚到底部。

## 4. 工作区、合同和执行语义

工作区是组织多个会话的高层对象，不等于目录、Git 仓库或 worktree。会话归属零个或一个工作区，每个会话一份独立合同。合同可选多个目录；不是让一个会话勾选多个工作区。

| 状态 | 读取 | 写入 | 合同编辑 |
|---|---|---|---|
| 无工作区、完全访问关 | 默认所有宿主可读位置 | 禁止修改用户资源 | 新增目录默认不可编辑，写开关不能打开 |
| 有工作区、完全访问关 | 默认所有宿主可读位置 | 可编辑目录及其子目录的并集 | 新增目录默认可编辑，可关闭 |
| 完全访问开 | 不受工作区/合同目录限制 | 不受工作区/合同目录限制 | 仍按是否归属工作区决定编辑器写开关行为 |

合同访问目录是默认上下文，不是读取白名单。用户在对话说“分析 D:/other”时直接处理，不要求先加入合同，不自动将该路径保存到合同。合同选择目录是在保存默认读取上下文与可选写授权；两者复用路径解析，但业务含义不同。用户没指定目录时模型自行选取合同中的一个或多个目录；空合同仍可聊天和处理命令中的路径。

有工作区即实现基础模式，目录为零不退回只读；没有“实现”按钮。完全访问是独立开关，保存在合同中，不是三模式选择器。模型不能自行打开完全访问。完全访问下用户要求“只分析”仍遵循命令。

不可编辑条目不构成拒绝规则：父目录可编辑、子目录不可编辑时子目录仍可编辑；父目录不可编辑、子目录可编辑时只授予子目录写权限。可写根取并集，路径按实际目标规范化，处理 Windows 大小写、junction 和符号链接，不用字符串前缀冒充边界检查。

权限不足由工具返回明确结果；无工作区说明“当前处于只读模式，未加入工作区”，有工作区未授权写入说明需要添加可编辑目录。读取不能因为合同外路径被拒绝。真实宿主权限仍如实反馈。

## 5. 新建、移动与继承

| 入口/操作 | 归属 | 合同 |
|---|---|---|
| 当前会话界面新建 | 继承当前归属 | 复制当前已保存合同，包括完全访问，保存为独立对象 |
| 工作区旁新建图标 | 目标工作区 | 初始化合同；有既定工作区预设时使用预设，无预设则空合同；不暗取其他会话 |
| 无历史、无工作区的新建 | 无工作区 | 默认空合同、完全访问关闭 |
| 移入/移出/跨工作区移动 | 更新归属 | 保留合同、目录写标记、完全访问及会话消息 |

工作区预设管理本期可不做；实施时核实服务现有初始化协议，不因缺少管理页面阻止创建。当前会话继承包括已保存待生效版本，不包括未保存表单；请求重试必须幂等。

移出工作区后原可编辑标记保留，但完全访问关闭时实际只读；界面说明“已保存为可编辑，当前只读模式不生效”。用户可以关闭原标记，不能打开新标记；重新加入工作区自然恢复合同授权。禁止移动时清空或重建合同。

## 6. 下一轮生效与持续执行

一轮是用户任务开始至回复结束或用户终止的完整执行周期，包含多次模型/工具调用和子任务。不是每次模型请求或工具调用。

服务在轮次开始原子读取归属、合同和版本，生成冻结快照；主 Agent 和本轮所有后续启动的 subagent 使用同一快照。运行中修改合同、移动和完全访问只改变已保存配置，下一轮生效；不能自动终止、重启当前轮或中途热更新权限。

桌面同时展示已保存版本与本轮有效版本，保存成功后刷新 Query 缓存。版本冲突提示重新载入/合并草稿，不静默覆盖他处修改。失败保留草稿，不显示虚假“已生效”。用户可主动停止，等停止完成后修改并发送“继续”。

运行中允许继续输入消息，使用服务持久队列并展示排队状态；不以 `SESSION_BUSY` 禁止用户表达。后续消息开始执行时取得最新已保存快照，按服务顺序处理，重试不重复执行。不得创建仅 Renderer 内存存在的任务邮箱。

取消前端写死模型轮次、编辑次数、自主等级和时长授权，也检查服务、Product 和执行器实际默认限制；把限额改为巨大数字不算完成。上下文压缩、可恢复限流和真实故障由执行循环处理，不要求普通工作反复补授权。用户主动停止与明确停止条件有效。

## 7. 服务、权限与 subagent 接入

建议逻辑模型包含：`workspaceId`、合同目录及 `writeEnabled`、用户工作要求、`fullAccess`、工作状态版本；轮次快照包含版本、基础/实际模式、默认目录、读取 ALL、写入 NONE/ROOTS/ALL。字段名称以核对后的 OpenAPI 为准，不在 Electron 另造不兼容协议。

调用链必须贯通：React → preload → 主进程服务客户端 → Service → 模型请求/工具执行器。核对已有 `SessionCreateRequest`、`SessionPatchRequest`、会话响应和事件；公共服务已有的实现直接复用，有缺口才扩展。单改 `api-types.d.ts` 不算接通。生成协议后检查漂移。

目录选择通过原生目录对话框和类型化 IPC，不让 Renderer 直接读文件系统。合同路径应属于 Agent 执行宿主；如使用远端服务，不能将本机选择器返回值当作远端有效路径，需要宿主路径输入/浏览能力和明确宿主说明。

只读工具要覆盖搜索、文件树、文件阅读、Git 阅读、跨目录分析。shell、MCP、hooks 和子任务不能绕过本轮写权限；只有提示词约束不算完成。不具备相应执行边界的工具返回具体不可用原因，其他读取继续；不得借此禁止整个无工作区会话。应用内部日志、会话状态写入自身状态目录，不写用户分析目录。

所有实际模式均向模型提供 subagent 能力，由模型按用户命令决定是否委派；禁止委派的用户命令应遵守。没有工作区、没有 Git、没有 Plan 页面都不能成为委派禁用条件。子任务继承父轮快照，父任务停止传播到子任务树；资源容量不足可排队，不能变成用户授权次数额度。失败由父模型决定后续处理。

完全访问绕过旧合同目录、风险分级、预算和逐项审批限制；未来统一执行禁止黑名单由用户配置为审批或拒绝，未命中不额外审批。IPC 身份校验、秘密保护和真实操作系统权限不属于需删除的产品行为限制。

## 8. 状态摘要的真实数据

| 指标 | 口径及呈现 |
|---|---|
| 净增删行数 | 显示 `+新增 / -删除`，相对本轮开始基线；不是工具调用次数，也不是只显示两数相减 |
| 变更文件数 | 同一基线下去重路径数，包含新增/删除/重命名；不能从 diff 当前分页长度推导总数 |
| Git 分支 | 多仓库分项显示；无 Git 显示“非 Git 目录”，不阻断工作 |
| worktree | 显示真实执行路径；直接目录与隔离 worktree 准确区分，多目录允许多个位置 |
| 当前动作 | 从实际运行事件显示搜索、阅读、编辑、测试、等待等和目标路径 |
| 累计活动 | 按稳定事件 ID 去重的已观察活动数，流重连不重复累计；新轮次明确重置范围 |
| subagent | 等待/运行/完成/失败/停止的数量及可展开子任务详情，不把未知状态画成零 |

净变更允许回落到零，不能为了表现工作伪造单调增加。累计活动作为持续工作的补充。二进制文件显示文件变更，不伪造行数；非 Git 目录有文件快照才能算净行数，没有基线就显示“暂无统计”。并发或外部编辑影响基线时注明“包含其他修改/归因不确定”，不能全算成 Agent 贡献。

服务提供全量摘要快照与增量事件，Renderer 复用订阅并节流渲染；断线后补快照、按序恢复去重。状态不可用显示未知/最后更新时间，禁止静态模拟活动冒充实时数据。摘要与详细 diff、事件和子任务均通过浮动面板按需查看，不增加固定列。

## 9. 历史与文档处理

历史会话不迁移，按公共 Service 一次性版本化清理处理消息、运行、事件、审批和 checkpoint 等引用关系。实施前核对当前工作树 `ControlPlaneMigration` 是否已完成该切换，避免桌面启动重复删除新历史。Desktop 清除对应旧选择缓存和失效会话引用，保留账号、连接、密钥和无关偏好；不是删除整个 SQLite 文件或用户目录。历史清理必须覆盖一次性执行和后续新数据保留测试。

冲突文档移入所属 `docs/del-doc` 并记录原路径、冲突点、替代文档；已归档内容不再次移动。本次已确认 `apps/codeagent-desktop/docs/ui-modernization-plan.md` 的命令面板、Mode picker 及禁止修改 main/preload 的规则与本方案冲突，实施时归档原文，保留其中独立有效的展示/性能建议。其他文档先逐项核对，不能仅凭日期批量归档。本文编写阶段不移动现有文件。

## 10. AI IDE 实施任务顺序

各阶段连续推进，不要求每阶段重新请用户批准；阶段只是验证与回滚边界。

1. **入口与基线**：检查工作树、项目指令、现有服务合同及脚本；记录桌面启动命令、实际 renderer 路径和当前截图。列出既有修改，避免覆写。
2. **桌面布局**：实现唯一标题行与真实窗口 IPC；移除旧顶栏、搜索、命令面板、CONVERSATION、旧模式选择及空白容器；建立左侧合同/配置、右侧 Git/状态浮动面板，支持左右独立开关和同时显示。保留左上 Logo，移除 Electron 菜单栏，确保固定布局只有两列。此阶段可以使用明确测试 fixture，但交付不得使用模拟状态。
3. **会话合同接入**：完成新建来源、移动、目录编辑、写开关、完全访问和版本冲突处理；清理旧 preflight 意图准入、硬编码参数。保持未保存草稿与已保存状态分离。
4. **执行贯通**：验证下一轮快照、持久消息队列、实际只读/可写范围、完全访问及三种状态下的委派；补齐服务缺口，不重复另造执行状态机。
5. **实时状态**：接入净 diff、仓库信息、活动和子任务；实现非 Git、未知、断线、分页及外部修改口径。
6. **收尾与交付**：核对一次性历史清理、归档冲突设计、更新 README 与实施记录；执行自动检查和真实 Electron 验收，提供修改后截图及准确启动步骤。

## 11. 必须通过的验收

| 场景 | 通过标准 |
|---|---|
| 空会话及已有会话 | 左上 Logo 保留，仅一行标题，右侧只有三个窗口控制；无菜单栏、CONVERSATION、消息计数、工作区顶栏和双搜索 |
| 窗口行为 | 最小化后恢复、最大化/还原、系统快捷键状态同步、拖动、关闭有效；没有双标题栏 |
| 1280×800、1920×1080、高 DPI | 左侧合同/配置与右侧 Git/状态入口一眼可见；左右可同时打开、独立关闭，组内切换不丢草稿；其他功能均为浮动面板，开关不改变两列宽高；面板不越界，中间无配置横幅与异常空占位 |
| 空合同只读 | 无工作区直接聊天，读取对话指定的合同外目录，搜索/树/阅读/Git/跨目录能力可用 |
| 只读修改 | 写入被实际工具拒绝；合同只能新增不可编辑目录；模型提示与实际状态一致 |
| 零目录工作区会话 | 保持实现基础状态，无实现按钮，没有目录写授权 |
| 父写子只读、父只读子写 | 分别按写授权并集生效，验证实际文件操作 |
| 移出再移入 | 原合同和写标记保留；只读时不生效，加入后恢复 |
| 新建入口 | 当前会话复制独立合同；工作区图标按初始化/预设；全局无上下文为空只读 |
| 完全访问 | 开关随合同继承，运行参数真正绕过目录限制，关闭回到归属对应模式 |
| 运行中修改/移动 | 当前轮和后启动子任务保持旧快照，下一轮使用新版本；没有隐式中断 |
| 运行中发消息 | 持久排队、重连可见、顺序执行、重试不重复，不返回会话忙来禁止输入 |
| subagent | 三种执行状态均可委派并继承权限；用户要求不委派时不启动；停止传播 |
| 状态面板 | diff 全量统计不受分页影响，重连不重复活动，无数据不伪造零 |
| 历史清理 | 只执行既定一次，后续创建的会话重启不丢失，设置及秘密保留 |

在 `apps/codeagent-desktop` 执行 `pnpm typecheck`、`pnpm test`、`pnpm build`（以 `package.json` 实际脚本为准）。如改公共协议/服务，运行相应合同、会话、执行器和迁移测试。已有测试中固化旧模式/审批的断言应替换为新语义，不能仅删除测试逃避验证。

构建成功后必须通过桌面 `pnpm start` 或项目真实启动脚本启动本次构建，核实 Electron 主进程和加载资源确属当前工程。至少保存空会话、运行会话、展开合同三张真实窗口截图，记录版本/构建时间。不能用 Web 页面、React mock 截图或仅 DOM 测试代替桌面窗口验收。若无法完成真实运行，明确标记该项未完成，不宣称用户截图问题已经解决。
