# CodeAgent Desktop：目录管理与工作区会话整理（讨论稿）

日期：2026-09-11。状态：讨论中，尚未实施。本次仅新增文档，不修改代码。

前一轮方案已实施（按用户反馈）；本稿记录下一轮优化方向，不代表以下内容已落地。原方案保留作为历史记录，本稿中明确的新决定优先于旧方案的冲突描述。

## 1. 本轮已明确的方向

- 删除“会话合同”这一产品名称及其复杂展示，重新收敛为目录管理。
- 目录管理只需要目录列表，支持添加、删除、修改路径和开启/关闭编辑能力，以标签显示状态。
- 工作区是组织会话的更高一级抽象；工作区下直接展示属于它的会话。
- 未归属工作区的会话默认只读。只读指不能修改用户资源，仍可发消息、阅读和分析，并非只能查看历史。开启“完全访问”后可以读写，无工作区会话同样适用。
- 保留“完全访问”按钮；开启后不受工作区归属、目录列表和目录编辑开关限制。提示词、能力及工具注入保持现有实现，本轮不调整，由用户决定如何使用模型。
- 删除“沿用合同新会话”入口和对应的专门创建流程。
- 删除会话区域的“配置”入口与浮动面板。
- 原“会话合同”入口改名，移入消息区底部、输入框左侧，与右侧 Git 入口对称。

## 2. 目录面板：一个列表就够了

建议入口及面板统一叫“目录”，使用文件夹图标。入口可显示数量，例如“目录 2”。“项目目录”也可用，但“目录”更短，也能容纳资料目录等非代码项目路径。

建议每行内容如下：

```text
目录                              [+ 添加目录]
D:\project\app          [可编辑 ✓]  [修改] [移除]
D:\reference            [可编辑 ○]  [修改] [移除]
```

以下目录编辑规则适用于完全访问关闭时；开启后目录仍可作为默认上下文，但编辑标签不限制实际读写，应显示“完全访问已开启”的简短提示。

“可编辑”标签本身就是开关，关闭时显示“只读”；不再拆成“写入根目录”和“可读目录”两张列表，也不额外增加一套权限表单。

| 操作 | 建议行为 |
|---|---|
| 添加 | 选择目录或输入路径；工作区会话默认可编辑，无工作区会话默认只读 |
| 修改 | 就地替换路径，保留该行编辑开关状态，校验通过后保存 |
| 移除 | 从当前会话的目录列表移除，不删除磁盘文件 |
| 开关编辑 | 同一行切换可编辑/只读；无工作区时不可打开编辑，并简短说明原因 |
| 查看长路径 | 行内省略，悬停或修改时查看完整路径 |

建议只补充必要细节：重复路径去重、无效路径就地提示、保存失败保留输入、空列表显示“添加目录”。先不加搜索、排序、分组、目录别名、主目录或额外标签系统。

这里暂将“开启关闭”理解为开启/关闭编辑能力。若还需要让某目录暂时不参与默认上下文，再单独讨论“启用目录”；不默认做两套开关。

建议逐项保存，修改路径时以确定/取消结束编辑；取消面板级“进入编辑—保存合同”的流程。运行中变更仍按下一轮生效，用一条短提示说明，不展示合同版本、权限摘要和执行模式卡片。

目录列表建议继续属于会话，工作区负责组织会话。将目录改为工作区共享会使一次修改影响多个会话，目前不把它加入本轮范围。

## 3. 工作区下直接放会话

```text
工作区                         [+]
▾ 产品开发                     [+] [⋯]
    登录页调整
    排查构建问题
▾ 数据工具                     [+] [⋯]
    导入脚本

只读会话                       [+]
    阅读源码
    分析日志
```

建议工作区名称负责展开/折叠，旁边的加号负责在该工作区新建会话；不要整行点击就新建。每个会话只出现一次，取消下方重复的全量平铺列表。

会话菜单提供“移至工作区”和“移出工作区”。移动保留消息和目录记录；完全访问关闭时，移出后目录实际全部只读；完全访问开启时，移出不收回读写能力。归属管理不放进目录面板。可后续讨论工作区改名、排序和删除，但这些不是目录面板的功能。

基础只读状态取决于真实工作区归属，实际读写还取决于完全访问开关，不能取决于工作区是否折叠、是否被筛选或是否暂未加载。工作区归属无法确认时应显示异常，不擅自改归属。

“只读会话”是默认状态分组；其中开启完全访问的会话应显示“完全访问”标记，避免让分组名称误导用户。分组是否改叫“独立会话”可继续讨论。

建议新建规则：工作区旁加号创建归属该工作区的新会话；“只读会话”旁加号创建无工作区会话。新会话不暗中复制当前会话目录；目录是否使用工作区默认值另行讨论，暂以空列表为基线。

## 4. 输入框两侧的入口

```text
┌ 导航 ──────────┬ 会话标题 ─────────────────────────┐
│ 工作区及会话树  │ 消息正文                          │
│                │                                   │
│                │ [目录 2]             [Git] [状态] │
│                │ ┌ 输入框 ───────────────────────┐ │
│                │ │                               │ │
│                │ └───────────────────────────────┘ │
└────────────────┴───────────────────────────────────┘
```

建议将“输入框左边”落实为输入区上沿同一行的左端，与右端 Git 对齐，不压缩文本输入宽度。目录面板从该入口向上展开，位于消息区内部；Git 从右端展开。维持导航、消息两列，面板不推挤正文。不在消息顶部或导航底部另留同名入口。

保留既有状态入口，本轮用户未要求删除。删除导航底部“会话合同 / 沿用合同新会话 / 配置”这一组按钮。

## 5. 删除范围与需要讨论的语义

旧面板的概念介绍、合同摘要、工作区选择、基础模式、版本展示、双目录列表和面板级编辑流程都移除。新会话页和详情页中残留的“空合同”“实现基座”“合同详情”等文案也应一起清理，不能只改一个按钮名称。

“配置”按本次上下文指会话旁的配置入口与中转面板；目前代码另有 Settings 页面，模型与连接等应用设置是否也调整不在这次已确认范围内。

以下先记录已确认的完全访问语义，再列出尚待讨论的细节：

完全访问已确认保留，不再作为待讨论项。它独立于工作区基础状态：关闭时使用基础只读/目录写入规则，开启时不受这些规则限制；只读会话也可开启。提示词、能力及工具注入沿用原有行为，不新增注入规则或模型行为约束。按钮具体位置尚待布局讨论。

1. **关闭编辑的精确含义（完全访问关闭时）。** 旧方案按可写目录并集计算，若父目录可编辑，关闭子目录编辑并不能禁止写入子目录。建议避免界面显示虚假的“只读”：重叠目录需要明确处理，不能仅更换标签。是否采用子目录显式只读覆盖父目录授权，留待讨论。
2. **运行中的移出工作区（完全访问关闭时）。** 旧方案在下一轮生效，意味着当前轮可能仍可写。建议运行时显示“移出将在本轮结束后生效”，完成后再归入只读列表；若要求立即转只读，则需要先停止当前轮，不能在列表已标只读时继续无提示写入。

目录只是默认上下文及写入范围管理，不因未添加某个目录就禁止读取用户在消息中指定的路径。无目录、无工作区也应能正常聊天和分析。
